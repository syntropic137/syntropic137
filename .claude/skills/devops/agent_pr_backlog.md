# Agent: PR backlog hygiene

## Purpose

Work every open PR to a known state and hand back a ready/blocked table with a
merge order. This agent makes PRs mergeable; it never merges and never closes.
Merging is `agent_pr.md` step 9 for whoever owns the decision, and closing an
obsolete PR is a call for the orchestrator or owner (recommend it, with the
reason). Run it when open PRs pass about 8: that number is a trigger to land
the backlog, not a cap that freezes dispatch.

## Workflow

1. Inventory:
   ```
   gh pr list --state open --limit 100 \
     --json number,title,headRefName,baseRefName,isDraft,mergeable,mergeStateStatus,reviewDecision,updatedAt,author \
     --jq '.[]|[.number,.isDraft,.mergeable,.mergeStateStatus,.headRefName,.updatedAt]|@tsv'
   ```
2. Skip branches that are live: a commit in the last 30 minutes, or a running Syntropic137 execution writing to that branch (ask the orchestrator if unsure). Pushing under a running agent forks its history.
3. For each remaining PR, in its own worktree (`../syntropic137_worktrees/pr-N`, `gh pr checkout N` inside it):
   - `git merge origin/main`. Resolve only mechanical conflicts: generated files (re-run `just codegen` and take its output), lockfiles (`uv lock`, `pnpm install`), `CHANGELOG.md` (take `main`'s; it is generated), import order, adjacent non-overlapping edits. A conflict that needs a semantic choice is a blocker; abort the merge (`git merge --abort`) and record it.
   - `git submodule update --init --recursive`, then `just preflight` and the PR's targeted tests. Stage by path, commit the merge, push normally. Never rebase, never force.
4. Rerun flakes once: `gh run rerun <run-id> --failed` for the flake classes in `agent_ci_triage.md`. A second identical failure is a defect; record the job and step.
5. Read review state: cross-family review present? findings answered? commits added after the last review (`git log --oneline <reviewed-sha>..HEAD --no-merges`)? Copilot comments open?
6. Classify each PR:
   - **ready**: green on the current head, merged with current `main`, review bar met, not draft.
   - **owner-gated**: green and reviewed, `mergeStateStatus == BLOCKED`. Touches `.github/CODEOWNERS` paths.
   - **needs review**: green, review missing or stale.
   - **blocked**: semantic conflict, real CI failure, or unanswered blocking finding (name it).
   - **recommend close**: superseded or obsolete (name the superseding PR or reason).
7. Order the ready set: `main`-red fixes first; then PRs others depend on (stacked bases, shared modules); then smallest diff first. Separate PRs that bump a projection `VERSION` (`git diff origin/main...<branch> | grep -E 'get_version|VERSION *='`) so they ship together in one rebuild window. Flag pairs that touch the same files: after the first merges, the second must merge `main` in and re-test before it merges.
8. Page the owner once with the owner-gated list and links, rather than leaving it in a report line.

## Output

| PR | Title | State | Evidence | Next action |
|---|---|---|---|---|

Followed by the merge order as a numbered list, and the recommend-close list.

## Health check

Depends on: `gh pr list` JSON fields above (`mergeStateStatus` values BLOCKED/DIRTY/UNSTABLE/CLEAN); `.github/CODEOWNERS`; `just codegen`, `just preflight`; `CHANGELOG.md` being generated by `scripts/changelog.py`; the worktree sibling directory convention. If merge policy changes (squash, rebase, auto-merge allowed), stop and update this file first.
