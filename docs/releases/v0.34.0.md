# v0.34.0 release notes (draft)

Draft body for the `main` -> `release` PR, which becomes the GitHub Release
notes ([release-process.md, step 3](../release-process.md#3-open-release-pr)).
`CHANGELOG.md` stays generated by `just changelog`; this file is the curated,
user-facing view of the same range (`v0.33.1..main`, 156 PRs).

---

## Highlights

- **Restart-safe executions.** Restarting or upgrading the API records every
  running execution `interrupted`, with its unpushed commits saved to a
  quarantine ref, so it can be resumed (#1730). Queued GitHub trigger starts
  survive a restart (#1759), and a resume continues at its own phase's pushes
  (#1749).
- **One concurrency limit, visible queue.** `SYN_EXECUTION_MAX_CONCURRENT`
  (default 4) covers every start path; the rest show as `queued` (#1574, #1751).
- **Evals.** A dashboard Evals section (#1712), an eval detail page built
  around variant comparison (#1772), `syn eval create` with frozen repo SHAs
  (#1649), and verifier-seed suite v6 with a train/holdout split (#1752, #1767,
  #1775, #1781). A verify run with no verdict now scores ERROR, not FAIL (#1783).
- **SDLC workflows certify sooner and stop sooner.** Review phases must report
  a verdict (#1761), repair rounds are capped at two (#1770), and the gates are
  read from the target repo (#1746).
- **Read path you can see.** A dashboard banner shows projection rebuild
  progress after a deploy (#1753); `/health` reports held and halted
  projections (#1737, #1701).
- **Operations.** Leaked workspace directories are reclaimed safely, with an
  optional disk pager webhook (#1755); containers carry host labels (#1736);
  `just pit-stop --service gateway` swaps the gateway alone (#1731); long
  history pages load in tens of milliseconds (#1580, #1636, #1695, #1694).
- **Security.** Envoy sidecar admin is locked to loopback (#1741).

## Upgrade Notes (read before upgrading, in this order)

### 1. AppArmor hosts: run `just apparmor-setup` BEFORE upgrading

The workspace images move to **Codex CLI 0.160.1** (#1723). Its sandbox adds a
read-only mask over `.aws`, which the old `agentic-codex-sandbox` AppArmor
profile denies. On a Linux host whose Docker enforces AppArmor
(`docker info --format '{{json .SecurityOptions}}'` contains `name=apparmor`,
e.g. Ubuntu 24.04), **every Codex phase is refused at provision** until the new
profile is loaded.

```bash
just apparmor-setup          # loads the profile from the new agentic-workspace pin
just apparmor-setup --check  # exit 0 = loaded and current
```

`just selfhost-update` runs this step for you before it restarts anything.
Without a checkout (npx install), copy the profile out of the API image: see
[docs/deployment/apparmor-codex-sandbox.md](../deployment/apparmor-codex-sandbox.md).
macOS / Docker Desktop: not affected.

### 2. Event store moves to v0.17.0

The API now uses the event-sourcing-platform **v0.17.0** SDK (#1737). Run the
v0.17.0 event store image with this release:
`ghcr.io/syntropic137/event-store@sha256:2f63a6cf4c8059471077f551ec6075525a0a3f4458feebfca24fd07a06d64a17`
(index digest, linux/amd64 + linux/arm64).

- The release compose now pins the event store from the ESP version this repo
  vendors, and the release fails if that image is not published. The old
  `event-store:latest` fallback is gone (#1573). If you hand-pinned the event
  store in your compose file, move the pin yourself: a pit stop /
  `selfhost-update` does not.
- Decoding is now strict. A payload that fails validation halts the
  subscription visibly instead of being skipped. Known legacy shapes are still
  tolerated. A scan of a 104k-event production store found no failures.
- `/health` gains two read-path states: `subscription.status: held` (a
  projection failed an event; see `held_projections`) and `halted` (an event
  could not be decoded; see `halted_at`). Both were invisible before. The
  execution read models now hold, rather than skip, a start event with an empty
  `execution_id` (#1701).

### 4. Memory defaults: API and event store 512m -> 2g; 8 GB host minimum

`API_MEMORY_LIMIT` and `EVENT_STORE_MEMORY_LIMIT` default to **2g** (were
512m). At 512m the API was OOM-killed under concurrent executions (#1552) and
the event store during projection rebuilds (#1553) (#1777).

- If your `infra/.env` sets either variable, **that value is kept**. Remove it
  or raise it to get the new default.
- The self-host minimum is now **8 GB RAM** (16 GB recommended). The control
  plane alone can reach about 6 GB; each running workspace can use up to
  `SYN_WORKSPACE_MEMORY_LIMIT_MB` (4096) on top. These are ceilings, not
  reservations.
- **Capacity check:** default concurrency goes from 1 to 4 (note 3), and each
  running execution holds a 4 GB / 2-CPU workspace. Make sure the host has the
  RAM, or lower `SYN_EXECUTION_MAX_CONCURRENT`.
- This is a stopgap: event store replay memory is still unbounded
  (syntropic137/event-sourcing-platform#406).

### 5. `api` stop grace period is now 200 s

On shutdown the API records each running execution `interrupted` after saving
its unpushed commits (#1730). The shipped compose sets the `api` container's
`stop_grace_period: 200s`, and uvicorn runs with
`--timeout-graceful-shutdown 30`.

- If you run your own compose file, add `stop_grace_period: 200s` to `api`.
  Docker's default of 10 s kills the API before it can record anything, and
  running executions are orphaned as before.
- If you raise `SYN_EXECUTION_INTERRUPT_BUDGET_S` to 75 s or more, raise
  `stop_grace_period` too.

### 6. Read models rebuild on first start

Nine read models and process managers are new or changed version since
v0.33.1, so the coordinator clears them and replays the event store from the
start on first boot:

| Projection | v0.33.1 | v0.34.0 |
|---|---|---|
| `workflow_execution_details` | 12 | 18 |
| `workflow_executions` | 6 | 10 |
| `workflow_details` | 9 | 12 |
| `workflow_summaries` | 4 | 6 |
| `artifact_summaries` | 6 | 7 |
| `evals` | new | 2 |
| `workspace_ownership` | new | 1 |
| `quarantine_notice` (process manager) | new | 1 |
| `execution_request_start` (process manager) | new | 1 |

There is one shared subscription, so **no read model advances until the replay
finishes**, not only these. The time is proportional to your event count.
While it runs:

- **The dashboard shows a rebuild banner** with exact progress, and the
  Executions, Evals and execution pages say when their own list is incomplete
  (#1753). The API reports the same as `read_model_status` on
  `GET /executions`, `GET /executions/{id}` and `GET /evals`, and
  `subscription.rebuilding_read_models` on `/health`.
- The executions list is **partial** and may miss recent runs; dashboard counts
  and pages lag.
- `GET /executions/{id}` can 404 for an execution that is running fine.
  `syn execution cancel / resume / inject` and `GET /executions/{id}/state`
  work during the rebuild if you pass the full id (#1732).
- `/health` shows `subscription.status: catching_up` with a `lag`. Top-level
  `status` stays `healthy`. **Do not treat 404s as data loss until
  `subscription.status` is `healthy`.**

Also on first start, a one-time backfill builds the new usage rollup table
(#1558). Until it finishes, `/health` answers `status: "starting"` (HTTP 200)
and every other route answers 503 with `Retry-After` (#1582). If you set
`SYN_SKIP_AUTO_CREATE_TABLES`, apply
`packages/syn-adapters/src/syn_adapters/projection_stores/migrations/007_agent_usage_rollup.sql`
(and `008_day_rollup_execution_index.sql`) by hand **before** starting: the API
refuses to start without them.

### 7. Reinstall the SDLC workflows

`sdlc-implement-v3` and `sdlc-reverify-pr-v1` now make **at most two**
fix/re-verify rounds (was three) (#1770), and their verify phases declare
`requires_verdict` (#1761). Installed workflows keep the old definition until
you reinstall them:

```bash
syn workflow install ./workflows/sdlc/implement-v3
syn workflow install ./workflows/sdlc/reverify-pr
```

A run still blocked after round 2 leaves its PR a draft with a comment naming
the open blocker. Progress for new runs counts out of 8 and 7 phases (was 10
and 9); existing executions keep their count. Eval verify workflows install as
revision `6.1.0` and also require a verdict (#1783).

### 8. Workspace access to the API: `SYN_PLATFORM_ACCESS_ENABLED` (off by default)

New in #1741, **off unless you set it**. Nothing changes for a workspace when
it is off: every workspace request to the API is refused, as before.

When set to `true`, each workspace phase receives `SYN_API_URL` and a
read-only `SYN_API_TOKEN`. The agent can GET executions, sessions, artifacts,
evals, insights and health, and nothing else; the API refuses every other
workspace request (401/403). Tokens are stored only as hashes, expire with the
phase (capped by `SYN_PLATFORM_ACCESS_TOKEN_TTL_SECONDS`, default 4 h) and are
revoked when the phase ends. Design:
[ADR-072](../adrs/ADR-072-workspace-platform-access.md).

### 9. API timestamps: workflow `created_at`

`/workflows` list and detail now serialise `created_at` as ISO 8601
(`2026-01-15T00:00:00+00:00`), not `2026-01-15 00:00:00+00:00`, and sort
newest-first by the recorded creation time again (#1778). The offset is
written `+00:00`, not `Z`; a client that parses strictly should accept both.

### 10. Workspace images

- **Claude Code CLI 2.1.293** in all workspace images (#1729). The
  `claude-cli` image jumps from 2.1.126; omni-agent and toolchain from 2.1.281.
- **Codex CLI 0.160.1** (#1723): see note 1.

### 11. Models

- **`gpt-sol` now resolves to `gpt-6.1-sol`** (also the Codex default),
  priced $2 / $10 per MTok in/out (#1686). `gpt-6-sol` stays priced for
  historical runs. Workflows that name `gpt-sol` change model on upgrade.
- **Claude Sonnet 5.5** (`claude-sonnet-5-5`) added, $2 / $10 per MTok in/out;
  the **`sonnet` alias now targets Sonnet 5.5** (#1713). Opus stays the default.
- `gpt-6-luna` is a known codex model, priced ($0.10 in / $0.50 out per MTok);
  no default model changes (#1740).

### 12. Workflow behaviour changes

- `syn workflow install` / `update` no longer archive workflows a package
  dropped. Pass `--prune` (with `--yes` when non-interactive) to keep the old
  behaviour (#1614).
- `-R <repo>` (and `repos` on the execute API) is no longer ignored for
  workflows with `requires_repos: false`: the repos are checked out and
  recorded, and an unreachable repo is refused with 422 (#1776, #1789).

### 13. Security

- **Envoy sidecar admin locked down (#1741).** Admin now listens on loopback
  only; port 9901, reachable from the agent network, serves `/ready` and
  nothing else. Before this, a workspace could call the admin API
  (`POST /runtime_modify`, `POST /logging`) and, for example, make Envoy log
  other workspaces' `Authorization` headers. Upgrading closes it; no action
  needed beyond running the new images.
- **Known posture, not changed in this release: workspace egress is open
  (#1794).** `agent-net` is a plain bridge network, not `internal: true`, so
  workspaces reach the internet directly rather than only through the Envoy
  proxy. A code comment claiming otherwise is wrong. Agents need package
  registries today, so this is documented rather than closed; the decision
  (allowlisted egress through Envoy, or keep open and pin the posture with a
  fitness test) is tracked in #1794. Treat anything a workspace can read as
  reachable from the internet.
- Dependency advisories cleared: katex, source-map-js (#1638); click 8.3.3 in
  the ui-feedback API, PYSEC-2026-2132 (#1531). The OSV scan was scanning
  nothing and now covers the nested lockfile (#1535).

## What's Changed

### Added

**Evals** (new section in the dashboard and CLI)

- **Dashboard Evals section**: every eval with pass rate, a sparkline of recent
  verdicts, and the workflow/model variants it has run with (#1712, backend
  #1711).
- **Eval detail page redesigned around variant comparison**: pass rate (ERROR
  and unscored excluded), PASS/FAIL/ERROR/unscored breakdown, median duration
  and cost, cost per PASS, and a `Best` badge once a variant has 3 judged runs.
  `GET /evals/{id}` returns a `stats` object (#1772).
- Executions list marks eval runs with an **Eval** badge: eval name and verdict
  (PASS / FAIL / ERROR / Unscored) (#1754).
- `syn eval create --name ... --goal ... [--repo owner/name@ref] [--workflow id] [--tag t]`
  creates an eval with each repo ref pinned to a commit SHA (#1649). Every run
  checks out those frozen SHAs (#1591).
- Workflows can declare `default_eval_id`; runs join that eval unless
  `--no-eval` (#1562).
- Eval suites: `evals/verifier-seed-v1` is now **v6**: 35 cases, 31 defects
  (24 mined from real fix PRs) and 4 clean controls, with a train/holdout split
  and a 30-day quiet-window rule for clean controls (#1683, #1700, #1750, #1752,
  #1767, #1775, #1781). Codex verifier variants pinned to `gpt-6-luna`,
  `gpt-5.6-luna` and `gpt-5.6-terra` (#1740). New implementer suite
  `evals/implementer-seed-v1` (#1747).

**Executions and workflows**

- Running executions are recorded `interrupted` on platform shutdown, with
  unpushed commits quarantined, so they can be resumed (#1730).
- Queued executions are visible in the dashboard and `syn execution list`
  (`--status queued`), with queue position and reason (#1751, #1574).
- New per-phase key `requires_verdict`: a review phase that reports no valid
  verdict fails as a resumable `platform` failure. A change certified on the
  first verify skips the repair rounds (#1761).
- `sdlc-implement-v3` and `sdlc-reverify-pr-v1` run the **target repository's
  own** verification gates, declared in a `## Verification gates` section of
  its `AGENTS.md` (#1746).
- Declared skill use is observable per phase: `phases[].skill_use` on the
  execution detail lists declared, invoked (with counts) and
  `declared_not_invoked` skills; codex phases report `not_observable` (#1674).
- Tags on workflows and executions: `tags:` in YAML, `syn workflow run --tag`,
  `syn execution list --tag`, and `syn execution|workflow tag add|remove`
  (#1526, #1541).
- Per-phase `max_cost_usd` cost limit (#1654).
- Per-phase `fallback_agent: {provider, model}`: re-run once on another
  provider when the first is at capacity or out of quota (#1663).
- `agent.require_delegation: true` fails a phase whose delegation never
  succeeded (#1590).
- A resumed run continues its parent's branch and draft PR (#1537), provisioned
  at the parent's recorded commits (#1525).
- Executions pinned to commits verify each repo's HEAD before the agent starts
  (`CheckoutMismatchError`) (#1615).
- When a failed or cancelled run's work is quarantined, the PR gets a comment
  with the ref and how to fetch it (#1589).
- Execution detail: every declared phase with Pending / Skipped (not needed) /
  Inherited states (#1703); the dispatch task, verbatim (#1561); per-phase
  `failure_classification`, `error_message`, `reported_failure_reason` on
  `GET /executions/{id}` (#1592).
- Workflow pages list each phase's skills with source and version (#1676).
- Agents see their deadline: `SYN_PHASE_DEADLINE`, `SYN_PHASE_TIMEOUT_SECONDS`
  (#1578).
- Workspaces tell pytest-xdist, vitest, cargo, make, uv, OpenMP and rayon the
  CPU limit, so they stop oversubscribing the host (#1687).
- Per-workspace resource usage (CPU, peak memory, OOM kills, disk, network)
  recorded at teardown as `workspace_resource_usage` (#1608).
- New workflow `sdlc-reverify-pr-v1` re-verifies an existing PR (#1653); SDLC
  verify screenshots UI changes at desktop and phone widths (#1648).

**Operations**

- Dashboard projection rebuild indicator and `read_model_status` in the API
  (#1753): see Upgrade Notes, item 6.
- Leaked workspace directories (crashed, OOM-killed or failed teardown) are

- Dashboard sidebar shows the running API version (#1548).
- `just pit-stop` proves a real execution starts before declaring DONE (#1644).
