## Upgrade Notes (read before upgrading)

### 1. AppArmor hosts: run `just apparmor-setup` BEFORE upgrading

The workspace images move to **Codex CLI 0.160.1** (#1723). Its sandbox adds a
read-only mask over `.aws`, which the old `agentic-codex-sandbox` AppArmor
profile denies. On a Linux host whose Docker enforces AppArmor
(`docker info --format '{{json .SecurityOptions}}'` contains `name=apparmor`,
e.g. Ubuntu 24.04), **every Codex phase is refused at provision** until the new
profile is loaded.

```bash
just apparmor-setup          # loads the profile from the new agentic-workspace pin
just apparmor-setup --check  # exit 0 = loaded and current
```

`just selfhost-update` runs this step for you before it restarts anything.
Without a checkout (npx install), copy the profile out of the API image: see
[docs/deployment/apparmor-codex-sandbox.md](../deployment/apparmor-codex-sandbox.md).
macOS / Docker Desktop: not affected.

### 2. Event store moves to v0.17.0

The API now uses the event-sourcing-platform **v0.17.0** SDK (#1737). Run the
v0.17.0 event store image with this release
(`ghcr.io/syntropic137/event-store@sha256:2f63a6cf4c8059471077f551ec6075525a0a3f4458feebfca24fd07a06d64a17`).

- The release compose resolves `event-store:latest` at release time (#1515,
  fix pending in #1573). **PENDING:** confirm `:latest` is still that digest
  when the release is cut. If you hand-pinned the event store in your compose
  file, move the pin yourself: a pit stop / `selfhost-update` does not.
- Decoding is now strict. A payload that fails validation halts the
  subscription visibly instead of being skipped. Known legacy shapes are still
  tolerated. A scan of a 104k-event production store found no failures.
- `/health` gains two read-path states: `subscription.status: held` (a
  projection failed an event; see `held_projections`) and `halted` (an event
  could not be decoded; see `halted_at`). Both were invisible before.

### 3. Read models rebuild on first start

Seven projections changed version since v0.33.1, so the coordinator clears them
and replays the event store from the start on first boot:

| Projection | v0.33.1 | v0.34.0 |
|---|---|---|
| `workflow_execution_details` | 12 | 18 |
| `workflow_executions` | 6 | 10 |
| `workflow_details` | 9 | 11 |
| `workflow_summaries` | 4 | 5 |
| `artifact_summaries` | 6 | 7 |
| `evals` | new | 2 |
| `quarantine_notice` (process manager) | new | 1 |
| `execution_request_start` (process manager) | new | 1 |

There is one shared subscription, so **no read model advances until the replay
finishes**, not only these. The time is proportional to your event count.
While it runs:

- The executions list is **partial** and may miss recent runs; dashboard counts
  and pages lag.
- `GET /executions/{id}` can 404 for an execution that is running fine.
  `syn execution cancel / resume / inject` and `GET /executions/{id}/state` now
  work during the rebuild if you pass the full id (#1732).
- `/health` shows `subscription.status: catching_up` with a `lag`. Top-level
  `status` stays `healthy`. **Do not treat 404s as data loss until
  `subscription.status` is `healthy`.**

Also on first start, a one-time backfill builds the new usage rollup table
(#1558). Until it finishes, `/health` answers `status: "starting"` (HTTP 200)
and every other route answers 503 with `Retry-After` (#1582). If you set
`SYN_SKIP_AUTO_CREATE_TABLES`, apply
`packages/syn-adapters/src/syn_adapters/projection_stores/migrations/007_agent_usage_rollup.sql`
(and `008_day_rollup_execution_index.sql`) by hand **before** starting: the API
refuses to start without them.

### 6. Settings: new, changed and removed

Defaults apply when unset; `.env.example` is regenerated.

| Setting | Default | Notes |
|---|---|---|
| `SYN_EXECUTION_MAX_CONCURRENT` | **4** | New. One limit for every start path (API, triggers, resume); the rest queue visibly as `queued`. Replaces `SYN_POLLING_MAX_CONCURRENT_DISPATCHES` (default was 1), **now ignored**. Size it as `(API_MEMORY_LIMIT_MiB - 128) / 96` and check host RAM covers that many workspaces (#1574) |
| `SYN_WORKSPACE_MEMORY_LIMIT_MB` / `SYN_WORKSPACE_CPU_LIMIT` | 4096 / 2.0 | New. Now actually applied to each workspace container (same as the previous effective default) (#1607) |
| `API_CPU_LIMIT` / `POSTGRES_CPU_LIMIT` | **2.0 / 2.0** | Were 0.5 / 1.0. Your `infra/.env` values still win (#1602) |
| `CONTROL_PLANE_CPU_SHARES` | 4096 | New. API, Postgres, event store and gateway get 4x a workspace's CPU weight under contention |
| `SETUP_PHASE_TIMEOUT_SECONDS` | **240** | Was 120 (#1748) |
| `SKILL_INSTALL_TIMEOUT_SECONDS` | 90 | New (#1748) |
| `CODEX_SANDBOX_PROBE_TIMEOUT_SECONDS` | 120 | New (#1748) |
| `CREDENTIAL_GUARD_EXEC_TIMEOUT_SECONDS` | 15 | New (#1748) |
| `CHECKOUT_VERIFICATION_TIMEOUT_SECONDS` | 60 | New (#1748) |
| `GITHUB_API_REQUEST_TIMEOUT_SECONDS` | 30 | New (#1748) |
| `SYN_DISK_PATH` | workspace dir | New. Filesystem measured by the disk check (#1577) |
| `SYN_DISK_DEGRADED_BELOW_PERCENT` | 10 | New. `/health` goes `degraded` (reason `disk_space`) below this |
| `SYN_DISK_REFUSE_ADMISSION_BELOW_PERCENT` | 5 | New. New executions refused with **HTTP 507** below this |
| `SLOW_REQUEST_LOG_THRESHOLD_MS` | 1000 | New. Requests slower than this are logged with route, status and DB-pool wait (#1584) |
| `SYN_SESSION_INVENTORY_PARK_SAFETY_SECONDS` | 900 | New |

**Removed** (they had no effect; delete them from your env): `DATABASE_POOL_SIZE`,
`DATABASE_POOL_OVERFLOW`, `SYN_WORKSPACE_POOL_SIZE`,
`SYN_WORKSPACE_MAX_CONCURRENT`, `SYN_WORKSPACE_ENABLE_CLOUD_OVERFLOW`,
`SYN_SECURITY_MAX_MEMORY`, `SYN_SECURITY_MAX_CPU` (#1607).

**Capacity check:** the default concurrency goes from 1 to 4, and each running
execution holds a 4 GB / 2-CPU workspace. Make sure the host has the RAM, or
lower `SYN_EXECUTION_MAX_CONCURRENT`.

### 7. Workflow package installs no longer prune

`syn workflow install` / `update` no longer archive workflows a package dropped.
Pass `--prune` (with `--yes` when non-interactive) to keep the old behaviour
(#1614).

## What's Changed

### Added

**Evals** (new section in the dashboard and CLI)

- **Dashboard Evals section**: every eval with pass rate, a sparkline of recent
  verdicts, and the workflow/model variants it has run with (#1712, backend
  #1711).
- Executions list marks eval runs with an **Eval** badge: eval name and verdict
  (PASS / FAIL / ERROR / Unscored) (#1754).
- `syn eval create --name ... --goal ... [--repo owner/name@ref] [--workflow id] [--tag t]`
  creates an eval with each repo ref pinned to a commit SHA (#1649). Every run
  checks out those frozen SHAs (#1591).
- Workflows can declare `default_eval_id`; runs join that eval unless
  `--no-eval` (#1562).
- Eval suites: `evals/verifier-seed-v1` (now v3: six defect + six clean control
  cases) (#1683, #1700, #1750) and the new implementer suite
  `evals/implementer-seed-v1` (#1747).

**Executions and workflows**

- Queued executions are visible in the dashboard and `syn execution list`
  (`--status queued`), with queue position and reason (#1751, #1574).
- Tags on workflows and executions: `tags:` in YAML, `syn workflow run --tag`,
  `syn execution list --tag`, and `syn execution|workflow tag add|remove`
  (#1526, #1541).
- Per-phase `max_cost_usd` cost limit (#1654).
- Per-phase `fallback_agent: {provider, model}`: re-run once on another
  provider when the first is at capacity or out of quota (#1663).
- `agent.require_delegation: true` fails a phase whose delegation never
  succeeded (#1590).
- A resumed run continues its parent's branch and draft PR (#1537), provisioned
  at the parent's recorded commits (#1525).
- Executions pinned to commits verify each repo's HEAD before the agent starts
  (`CheckoutMismatchError`) (#1615).
- When a failed or cancelled run's work is quarantined, the PR gets a comment
  with the ref and how to fetch it (#1589).
- Execution detail: every declared phase with Pending / Skipped (not needed) /
  Inherited states (#1703); the dispatch task, verbatim (#1561); per-phase
  `failure_classification`, `error_message`, `reported_failure_reason` on
  `GET /executions/{id}` (#1592).
- Workflow pages list each phase's skills with source and version (#1676).
- Agents see their deadline: `SYN_PHASE_DEADLINE`, `SYN_PHASE_TIMEOUT_SECONDS`
  (#1578).
- Workspaces tell pytest-xdist, vitest, cargo, make, uv, OpenMP and rayon the
  CPU limit, so they stop oversubscribing the host (#1687).
- Per-workspace resource usage (CPU, peak memory, OOM kills, disk, network)
  recorded at teardown as `workspace_resource_usage` (#1608).
- New workflow `sdlc-reverify-pr-v1` re-verifies an existing PR (#1653); SDLC
  verify screenshots UI changes at desktop and phone widths (#1648);
  `sdlc-implement-v3` makes up to three fix/re-verify rounds (#1613).

**Operations**

- `/health`: workspace-volume `disk` block (#1577) and
  `subscription.unapplied_starts` for start events a read model skipped
  (#1550).
- Gateway access log adds `rt= uct= uht= urt=` timings (#1584).
- Dashboard sidebar shows the running API version (#1548).
- `just pit-stop` proves a real execution starts before declaring DONE (#1644).

### Changed

- **Performance:** executions, execution detail, sessions and artifacts pages
  load in tens of milliseconds on long-history installs (#1580, #1636, #1695,
  #1694); metric cards and heatmap read a rollup table (#1558); the Repos page
  caches the App's repo list for a minute (#1671). The API now uses the stdlib
  event loop (#1691).
- Workflow phases `premise`, `prepare` and `finalize` run on Opus 5.5 (#1666).
- Agent workspaces no longer load a repo's instructions twice when `AGENTS.md`
  duplicates or points at `CLAUDE.md` (#1738).
- Event store SDK v0.17.0 (#1737), Claude Code 2.1.293 (#1729), Codex 0.160.1
  (#1723): see Upgrade Notes.

### Fixed

- A Redis timeout during dedup could drop a first-seen GitHub event as a
  duplicate (#1757).
- Cancelling a queued execution now withdraws it, also across restarts (#1651).
- Binary artifacts (PNG, PDF, ...) are kept byte-for-byte; new
  `GET /artifacts/{id}/raw` (#1652).
- Phases that declare skills can invoke them (#1540).
- `syn workflow install` handles YAML anchors and merge keys instead of
  silently dropping phases (#1619); `syn workflow run -t ""` is refused (#1621).
- Execution progress no longer counts repair rounds a certifying review made
  unnecessary (#1681).
- Workspace provisioning and GitHub token mints retry through dropped
  connections and 5xx bursts (#1611, #1709); exec `-1` with no output is retried
  and explained (#1692); codex sandbox probe no longer fails on a missing
  `TMPDIR` (#1706).
- Repos page lists every connected repo (#1668), shows correct attachment
  badges (#1579), and no longer shows an unreachable repo as public (#1685,
  #1680); Live Commits validates SHAs (#1679).
- Dashboard: run-status chart shows running/cancelled/interrupted (#1564);
  workflow search covers all workflows (#1566); feedback widget fixes (#1576,
  #1603, #1667).
