### Fixed

- `GET /metrics` now returns `total_cost_display` and `unpriced_observation_count`, counted from the same canonical usage as `total_cost_usd`. A total that includes work we could not price reads `unpriced` or `>=$X (partial)` instead of looking complete. `total_cost_usd` itself is unchanged. (#2338)
- `syn costs summary` and `syn events costs` no longer show unpriced work as `$0.00`, and no longer show a partial total as if it were complete. They now print the API's verdict: `unpriced`, or `>=$X (partial)`. When some usage could not be priced, a line follows that says how many observations had no rate. (#2337)
- Repo and system cost totals now include work priced from its tokens that was previously omitted, and report how much could not be priced. `GET /repos/{id}/cost` and `GET /systems/{id}/cost` gain `unpriced_observation_count` and `total_cost_display` (`unpriced` or `>=$X (partial)` when coverage is incomplete). Expect these totals to rise. `/systems/{id}/cost` totals now match `/insights/cost?system_id={id}`, and the scoped insights total no longer drops a system's older work. (#2330)
- A phase's `max_cost_usd` limit now prices Claude's 1-hour prompt-cache writes at the 1-hour rate (2x input) instead of the 5-minute rate (1.25x). Phases now stop at their declared limit instead of overspending it. (#2329)
- `syn insights cost` no longer prints a bare dollar total when some usage could not be priced. It now shows the API's verdict: `$X.XX` when fully priced, `>=$X (partial)` when some usage had no rate, or `unpriced` when none of it did. When usage is missing from the total, it adds a line saying how many observations had no rate. (#2327)
- fix(workflows): give implement and fix phases 90m, since the gates alone take ~20m (#2320) (#2325)
- `GET /insights/cost` now says when its total is incomplete. Responses add three fields: (#2324)

Its reason names the phase, the skill, its source and how to register it (`syn skill add` or `POST /skills/registrations`). No execution is started. Before, it showed only a generic `start_exception`, and only after an execution task had been spawned and had failed. (#2322)
- A remote session-store receipt now counts as a present replica only when it acknowledges the exact transcript revision syn137 archived. Mismatched receipts are retried and are not reported as captured. (#2312)

- Fixed: a phase that produced a large text artifact (for example a multi-megabyte CI log) no longer fails after completing with an event store `OUT_OF_RANGE` error. Text artifacts over 512 KiB are now kept in object storage, and the API and the next phase read them from there. (#2306)
- fix(orchestration): accept only git hook events from tool output (#935) (#2305)
- **Fixed:** an organization's repository count now goes down when a repository is deregistered. Before this fix, the count on the organization list and organization detail views included every repository ever registered. (#2304)

- `GET /workflows?order_by=…` now orders the whole workflow list before paging, so page 2 continues page 1. Counts sort numerically (10 after 9 when descending). The dashboard's "Recent Workflows" list now shows the most-run workflows. (#2299)
