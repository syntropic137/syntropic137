Control running executions

## `syn control cancel`

Cancel a running execution

```bash
syn control cancel <execution-id> [options]
```

**Arguments:**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `execution-id` | `text` | Yes | Execution ID to cancel |

**Options:**

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--reason`, `-r` | `text` | --- | Reason for cancelling |
| `--force`, `-f` | `boolean` | `false` | Skip confirmation prompt |

Cancelling a started execution is asynchronous: the signal is queued and the executor acts on it shortly after. Until then the response's state, and any re-read, still shows the state before the cancel (usually running), and the command says the cancel is queued. Run `syn execution show <execution-id>` until it reads cancelled. Cancelling a start that is still queued withdraws it at once: it reads cancelled straight away and never runs.

## `syn control inject`

Not supported: the API refuses it. Cancel the execution and start again with a corrected task

```bash
syn control inject <execution-id> [options]
```

**Arguments:**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `execution-id` | `text` | Yes | Execution ID |

**Options:**

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--message`, `-m` | `text` | --- | Message to inject |

|------|------|---------|-------------|

Cancelling a started execution is asynchronous: the signal is queued and the executor acts on it shortly after. Until then the response's state, and any re-read, still shows the state before the cancel (usually running), and the command says the cancel is queued.
