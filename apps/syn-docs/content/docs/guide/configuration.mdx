Syntropic137 uses environment variables for configuration. Copy `.env.example` to `.env`
and customize as needed.

## Core Settings

| Variable | Default | Description |
|----------|---------|-------------|
| `APP_ENVIRONMENT` | `development` | Runtime environment (`development`, `beta`, `staging`, `production`, `selfhost`, `test`, `offline`) |
| `SYN_OBSERVABILITY_DB_URL` | | PostgreSQL connection string the API uses for observability data and projections |
| `DATABASE_URL` | | PostgreSQL connection string for the event store container (set in Docker Compose) |
| `REDIS_URL` | | Redis connection string |
| `SYN_API_HOST` | `0.0.0.0` | API server bind address |
| `SYN_API_PORT` | `8000` | API server port |

## GitHub App

Syntropic137 integrates with GitHub through a GitHub App for receiving webhook events
and managing repositories.

### Setup

The GitHub App is created during setup:

```bash
npx @syntropic137/setup init
```

To open an existing App's settings, permissions or installations page later, run
`npx @syntropic137/setup github-app`.

See [GitHub Integration](/docs/guide/github-integration) for the full setup guide including trigger rules and webhook configuration. For secret storage details, see [Secrets Management](/docs/guide/secrets).

### Environment Variables

| Variable | Description |
|----------|-------------|
| `SYN_GITHUB_APP_ID` | GitHub App ID |
| `SYN_GITHUB_APP_PRIVATE_KEY_FILE` | Path to the PEM private key file (preferred; takes priority) |
| `SYN_GITHUB_PRIVATE_KEY` | Private key as `file:<path>`, raw PEM, or base64 PEM (fallback) |
| `SYN_GITHUB_WEBHOOK_SECRET` | Webhook verification secret |

## Execution Concurrency

One budget bounds how many workflow executions run at once, across every
start path: `syn workflow run` / `POST /workflows/{id}/execute`, trigger
dispatch and resume. Starts beyond it wait in a first-come queue and show as
`queued`, with their position, in `syn execution show <id>`.

| Variable | Default | Description |
|----------|---------|-------------|
| `SYN_EXECUTION_MAX_CONCURRENT` | `4` | Executions one API process runs at once |

The limit is about memory. Every running execution holds a workspace container
and roughly 96MiB of API memory, and an API that exceeds `API_MEMORY_LIMIT` is
killed along with every execution it hosts. The default of `4` is conservative
for the `2g` API default; size it as `(API_MEMORY_LIMIT in MiB - 128) / 96`,
for example `20` for `2g`, and make sure the host has RAM for that many workspaces. The API logs
a warning at startup when the two disagree.

## Event Polling

Syntropic137 polls the GitHub Events API as a zero-config fallback when webhooks
are unavailable. Polling is **enabled by default**, no tunnel setup required.
See [Event Ingestion](/docs/guide/event-ingestion) for how the hybrid approach works.

| Variable | Default | Description |
|----------|---------|-------------|
| `SYN_POLLING_DISABLED` | `false` | Disable Events API polling entirely |
| `SYN_POLLING_POLL_INTERVAL_SECONDS` | `60.0` | Active polling interval (seconds) |
| `SYN_POLLING_SAFETY_NET_INTERVAL_SECONDS` | `300.0` | Safety net polling interval (seconds) |
| `SYN_POLLING_WEBHOOK_STALE_THRESHOLD_SECONDS` | `1800.0` | Seconds before switching to active polling |
| `SYN_POLLING_DEDUP_TTL_SECONDS` | `86400` | Dedup key TTL (seconds). Stored in Postgres when available, rounded up to whole days; Redis is the fallback |

See `.env.example` in the repository for the complete list of configuration
options.
